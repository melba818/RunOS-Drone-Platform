# RunOS 算力节点

入口：`/compute-nodes`；HTTP 路由：`routers/compute_nodes.py`。

节点模块提供 CRUD、SSH 身份校验及只读系统/GPU/Python 环境检测。
模型训练页已接入 SSH 远程 YOLO / RF-DETR 目标检测；API 连接方式仍预留。
不会自动安装软件、杀进程或管理其他用户任务。

## 使用

1. 添加 SSH 节点，填写地址、端口、用户名、工作目录和 Python 环境。
2. 输入密码或 PEM/OpenSSH 私钥（支持 RSA、ECDSA、Ed25519），可填写密钥口令。
3. 首次测试会显示 SHA256 Host Key 指纹；与服务器管理员核对后勾选确认、信任，再次测试。
4. 保存节点时勾选保存凭据；后续同一 Windows 账户启动 RunOS 无需重新输入。
5. 修改配置后用“测试连接”；右侧“重新检测”检测最后保存的节点配置。
6. Conda 若未加入登录 shell 的 PATH，可填 `/opt/miniconda3/bin/conda` 等绝对路径。
7. GPU/环境结果为最近一次检测快照，不表示持续在线监控；进程数仅 NVIDIA 计算进程。

## 存储与安全

- `workspace/compute_nodes/nodes.sqlite3` 存配置、检测快照、Host Key 和加密凭据。
- 凭据使用 Windows DPAPI 当前用户范围加密；没有前端密钥或明文密码字段。
- 选择 DPAPI + SQLite 是为了同时支持较长 SSH 私钥和密码，并由 Windows 管理加密密钥。
- 仅节点 ID、credential_id 和已保存状态返回前端；验证错误不回显请求体。
- 未勾选保存的凭据只在当前后端进程内存中有效。
- 数据库复制到其他 Windows 账户/电脑不能直接解密凭据，需要重新输入。
- 接口仅接受本机请求，浏览器 Origin 限于本机 RunOS 3000 端口。
- 首次连接不会自动接受 Host Key；变化时拒绝连接，不自动覆盖已信任指纹。
- 不暴露任意 shell 命令接口；检测命令固定，环境名称/路径均验证并 shell 引号转义。
- 连接、认证和命令有超时，输出有大小限制，同节点避免并发探测，总并发上限 4。
- SFTP 基础上传/下载供后续后端服务复用，本期没有上传/下载 HTTP 接口或前端入口。

## 远程训练

SSH 上传、启动、状态查询和结果下载各自使用独立连接；SFTP 离开上下文时显式关闭。
连接使用 30 秒 keepalive，执行前检查 Transport 活性。传输异常单次重连重试；监控掉线继续重连。
启动重试受 launch.pid 与 runner.lock 保护，避免回执丢失后重复训练。runner.pid 在导入训练包前写入，
确认 PID 存在且训练状态为 running 后才标记运行中。remote_pid、remote_workdir、log_path 随任务保存；
重启后已提交任务只恢复监控，未完成上传的任务明确报错，不将半成品作为完整数据集启动。

训练页选择本地电脑或已配置 SSH 节点。当前远程支持 YOLO / RF-DETR 检测和独立 YOLO 格式
Split 数据集（data.yaml + train/val 图片、对应 bbox 标签；不支持远程 ReID、分类或分割）。
服务器必须事先安装 CUDA PyTorch、对应训练包；RF-DETR 使用本机已验证的 1.9 API，并需要
训练依赖及 Albumentations。环境不满足时返回错误，不自动装包或回退本机/CPU。

- 以只读快照打包当前数据集和初始权重，拒绝引用所选数据集目录外文件。
- 每个任务在工作目录下创建独立 `runos_jobs/<id>_<随机值>/`，不会覆盖其他用户目录。
- 上传 runner、现有 training.py 和 RF-DETR 适配文件，复用原训练引擎。
- POSIX `nohup` 启动选定环境 Python；独立锁阻止重复启动。
- 原子状态文件回传 Epoch/Loss/mAP；模型完成后下载到本机 workspace/models，前端可下载。
- SSH 断线重连只恢复监控，不重新提交任务。保存凭据时，本机后端重启可恢复已提交任务监控。
- 停止通过本任务目录中的 STOP 文件请求，只作用于当前任务；等待批次/轮次完成，不发 kill。
- 暂不支持远程暂停/断点续训。关闭本机 RunOS 不会自动停止远程已提交任务。
- 自动 GPU 当前选择检测列表首卡，不代表空闲卡调度；公共服务器使用者应自行选择获准使用的 GPU。
- 远程任务目录和快照保留便于排查；不自动删除服务器数据。

验证：本机 CPU 隔离数据完成真实 YOLO 1 epoch，确认 loss/权重/源标签不变；另有分发、
凭据隔离、状态回传、模型下载路径限制、STOP 隔离及重复启动测试。真实 Linux GPU 服务器
训练、断线恢复和吞吐性能尚未进行实机验收。

## 远程推理

推理页可选择本地电脑或 SSH 算力节点。YOLO / RF-DETR 的图片、图片文件夹、视频与摄像头
复用现有推理引擎、参数、类别筛选和绘制；模型上传一次后缓存。摄像头仍在本机采集，
通过本地后端发送最新画面，网络耗时计入摄像头显示的推理耗时。智能模型和自定义 ReID 暂限本地。

- SSH/SFTP 使用已保存凭据与主机指纹；前端仅调用本地 HTTP。
- 服务器需预先具备 CUDA PyTorch、Ultralytics/RF-DETR、FastAPI、uvicorn、python-multipart
  及现有引擎依赖，SSH 必须允许 direct-tcpip 转发。不会自动安装或回退本机/CPU。
- 上传到独立 `runos_inference/<随机值>`；私有服务仅监听服务器 127.0.0.1，使用随机令牌。
- 视频结果通过 SSH 流式下载；基础跟踪复用原引擎。任务绑定原 worker，本机后端重启后可按任务 ID
  在该节点自有工作目录重新定位仍存活的 worker；不会为查询进度创建新进程。远程 worker 退出后不保证恢复。
- 空闲 15 分钟释放模型缓存；无视频结果时退出。关闭本地后端请求自有进程在视频完成后退出。
- 远程文件保留，不自动删除服务器数据。实时性能取决于网络和 GPU，不保证与本地摄像头同帧率。

验证：隔离 CPU worker 经真实 SSH 转发完成 YOLO/RF-DETR 图片、类别筛选、连续帧与短视频；
未连接用户真实 GPU 服务器。部署 SFTP 和 Linux GPU 环境仍需实际节点验收。
